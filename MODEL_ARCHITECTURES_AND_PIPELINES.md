# C 1s peak-property models

This document describes `c1s_peak_cnn.ipynb`, `c1s_peak_transformer.ipynb`, and `c1s_peak_vae.ipynb`. All three notebooks train on the same SESSA data and predict the same peak properties. They differ in how they represent the input spectrum.

## What one prediction contains

The dataset has five named C 1s components: `CC` (C–C/C–H), `CO` (C–O), `CARBONYL` (C=O), `OCO` (O–C–O), and `COO` (carboxyl-type carbon). For **each** component, every model predicts:

| Property | Meaning | Source of the training label |
| --- | --- | --- |
| Presence probability | Likelihood that the component is included in the SESSA simulation. A value of at least 0.5 is called present. | `presence` |
| Center, eV | Binding-energy position assigned to that peak. | `center_ev` |
| FWHM, eV | Effective full width at half maximum of the simulated component after SESSA processing and analyzer broadening. | Calculated from `component_relative` |
| Area | Area of the component over the 280–300 eV window, in relative-intensity × eV units. | `component_area_window` |
| Shape | One of Gaussian, Lorentzian, or pseudo-Voigt. | `shape_code` |

Thus, a model does **not** merely output five composition percentages. It outputs enough information to construct one approximate peak curve for every component called present. The area is relative to the SESSA clean spectrum's normalization; it is not an absolute measured count rate or an atomic percentage. The FWHM is an *effective width of the saved component curve*, not the intrinsic Gaussian or Lorentzian width entered into SESSA. A shape label is predicted separately from the width.

Each model's final layer has **35 raw values**: seven for each of five components. Within each set of seven, one value is a presence score, one produces the center, one produces FWHM, one produces area, and three are scores for the possible shapes. The center is constrained to within 0.6 eV of that component's nominal position. FWHM is constrained to 0.4–1.6 eV, and area is constrained to be positive. These ranges cover the labels generated by the current SESSA script.

## Shared data pipeline

The notebooks expect `dataset.npz` from `generate_sessa_training_dataset.py`. The first code cell contains `data_path`; set it to the complete dataset on the training machine. The current generator uses a 401-point C 1s grid from 280 to 300 eV and saves three noisy count observations per simulated case. The notebook reads the noisy observations as inputs and repeats the same peak labels for all three observations of a case.

Before a spectrum enters a model, the notebook:

1. Takes the mean of the first 10 intensity values and of the last 10 values.
2. Subtracts the straight line between these two means as a simple baseline.
3. Clips negative results to zero.
4. Divides by the remaining maximum so the input lies between 0 and 1.

A peak's FWHM label is found from its saved, noise-free `component_relative` curve by locating the two energies where intensity falls to half of that component's maximum. The notebook interpolates between adjacent energy-grid points at each crossing. This calculation is performed only for components that are present. The other labels come directly from the NPZ file.

The NPZ's `train`, `validation`, and `test` case labels are preserved. All noisy observations generated from the same SESSA case stay in the same split. This prevents a noisy copy of a training case from appearing in validation or test data.

## CNN architecture

`c1s_peak_cnn.ipynb` processes the spectrum as a one-dimensional signal. Three convolution layers look for local patterns and reduce the number of energy positions. A small dense head then produces the 35 raw property values.

| Stage | Output size for a 401-point input |
| --- | --- |
| Input spectrum | 1 × 401 |
| Convolution 1: 16 filters, width 7, stride 2, ReLU | 16 × 201 |
| Convolution 2: 32 filters, width 5, stride 2, ReLU | 32 × 101 |
| Convolution 3: 64 filters, width 5, stride 2, ReLU | 64 × 51 |
| Adaptive average pooling | 64 × 16 |
| Flatten and dense layers, 1024 → 64 → 35 | 35 values |

Keeping 16 pooled positions allows the dense layers to use information about where a peak occurs on the energy axis. The notebook saves the best validation checkpoint as `outputs/sessa_models/cnn.pt` when run.

## Transformer architecture

`c1s_peak_transformer.ipynb` first converts the 401-point spectrum into 51 tokens, each with 32 values. It adds a learned position vector to each token so that a feature at 285 eV is distinguishable from one at 289 eV. Two Transformer encoder layers then let different energy regions exchange information through attention.

| Stage | Output size |
| --- | --- |
| Convolutional embedding, 1 → 32 channels, width 7, stride 8 | 51 × 32 tokens |
| Learned position vectors | 51 × 32 tokens |
| Two encoder layers, 4 attention heads, 64-unit feed-forward part | 51 × 32 tokens |
| Mean of the 51 encoded tokens | 32 values |
| Dense layers, 32 → 32 → 35 | 35 values |

Encoder dropout is 0.1. The best validation checkpoint is saved as `outputs/sessa_models/transformer.pt` when run.

## VAE architecture

`c1s_peak_vae.ipynb` combines a variational autoencoder with a supervised property head. An encoder compresses the whole spectrum, and two small layers describe a distribution over 16 latent values. During training, the model samples from this distribution. During evaluation it uses the latent mean, making predictions deterministic.

| Stage | Output size |
| --- | --- |
| Encoder, 401 → 128 → 64 with ReLU | 64 values |
| Separate mean and log-variance layers | 16 + 16 values |
| Sampled latent vector during training; mean at evaluation | 16 values |
| Decoder, 16 → 128 → 401 with ReLU and sigmoid | Reconstructed normalized input spectrum |
| Property head, 16 → 35 | 35 property values |

The VAE's decoder reconstructs the **preprocessed noisy input**, not a clean spectrum or a set of individual peaks. The property head supplies the peak table. The best validation checkpoint is saved as `outputs/sessa_models/vae.pt` when run.

## Training loss and model selection

All models use a batch size of 128, Adam with learning rate 0.001, 12 epochs, and random seed 42. The notebook uses a GPU when available. After each epoch, it measures validation loss and saves the weights if that loss improved. The test and real-data cells reload these best saved weights.

The property loss contains five terms:

- Binary cross-entropy for presence.
- Squared error for center, after division by 0.5 eV.
- Squared error for FWHM, after division by 1 eV.
- Squared error for area, after division by 2 relative-intensity × eV units.
- Shape cross-entropy, multiplied by 0.25.

Center, FWHM, area, and shape losses use only peaks that are truly present. The VAE also adds `0.1 × reconstruction MSE` and `0.001 × KL loss` to regularize its latent representation. The weights set the relative importance of the loss terms; they do not change the units shown in the evaluation table.

## Accuracy on held-out SESSA cases

Each notebook prints and saves a test table for every component and an `ALL` row. It reports:

| Metric | Interpretation |
| --- | --- |
| Presence precision | Among peaks called present, the share truly present. |
| Presence recall | Among truly present peaks, the share detected. |
| Presence F1 | Combined precision and recall. |
| Center MAE, eV | Average absolute center error for truly present peaks. |
| FWHM MAE, eV | Average absolute width error for truly present peaks. |
| Area MAE | Average absolute area error for truly present peaks, in relative-intensity × eV units. |
| Shape accuracy | Share of truly present peaks assigned the correct shape class. |

Property errors are calculated on truly present peaks **even if the presence decision was wrong**, so missed peaks do not disappear from the center, FWHM, area, or shape assessment. Presence is evaluated separately at the fixed 0.5 threshold. The test table is saved as `outputs/sessa_models/<model>_test_metrics.csv` when a notebook runs.

## Three best and three worst plots

Each notebook uses a simple peak formula to draw spectra from the **true** SESSA peak properties and from its **predicted** properties. It integrates the absolute difference between these two curves and divides by the integrated true curve area. The three lowest-error and three highest-error test scans are plotted, with at most one scan from any SESSA case in each group. This produces a six-panel figure and saves it as `outputs/sessa_models/<model>_best_worst.png`.

The plots compare reconstructions from *peak-property tables*. They are not plots of an exact SESSA physical simulation: SESSA also includes instrument and scattering effects that the simple profile formula does not reproduce.

## Predictions on real measurements

The final cell downloads six real C 1s measurements from the [Zenodo dataset](https://zenodo.org/records/4624072) accompanying [*Pre-deliquescent water uptake in deposited nanoparticles observed with in situ ambient pressure X-ray photoelectron spectroscopy*](https://acp.copernicus.org/articles/21/4709/2021/): sucrose at 0, 0.2, 1, and 5 mbar, and malonic acid at 0.2 and 1 mbar. It uses the first C 1s region in each file, averages repeated scans, converts kinetic to binding energy, interpolates to the SESSA grid, and applies the same baseline correction and scaling. The Zenodo `MalonicAcid_0mbar.xy` file contains overview data but no C 1s region, so it is omitted.

For each real measurement, the final cell displays the predicted presence probability, presence decision, center, FWHM, area, and shape for each component. It does not export a peak table. These properties can be used later to construct approximate peak curves.

The best/worst plots use a Gaussian (`η = 0`), Lorentzian (`η = 1`), or fixed 50:50 pseudo-Voigt (`η = 0.5`). With binding energy `E`, center `c`, FWHM `w`, curve height `H`, and Lorentz fraction `η`, the peak is:

```text
d = (E - c) / w
G(E) = exp(-4 ln(2) × d²)
L(E) = 1 / (1 + 4d²)
peak(E) = H × [(1 - η)G(E) + ηL(E)]
```

For the best/worst plots, `H` is calculated so that the curve integrates to the predicted area over the 280–300 eV grid. The pseudo-Voigt fraction is a fixed plotting choice, not a learned SESSA mixing parameter. This simple reconstruction does not include a fitted experimental background or absolute count calibration.

The real Zenodo spectra do not have labels in the same five-property SESSA format. The final cell shows what the models predict; the held-out SESSA table provides the quantitative property accuracies. Real-data accuracy would require an independently reviewed experimental peak fit.
